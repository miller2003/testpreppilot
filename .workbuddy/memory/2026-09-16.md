## 首页筛选器移动端重构（全部改在 src/pages/index.astro）

用户反馈手机端筛选排布差，要求 PC 端保持原样、移动端改成一个筛选按钮 + 弹层。已实现并用真机视口（无头 Chrome + CDP）逐项验证。

- **单 DOM、双布局**：外壳 `.filter-shell` / 面板 `.filter-panel` 在桌面是 `display: contents`（表单原封不动当 flex item 用），≤900px 才变成 `position: fixed` 遮罩 + 底部弹层。没有复制控件、没有 ID 冲突，桌面那一行的几何和之前逐像素一致（bar 高 67px）。
- **断点 900px**，与 Header 的汉堡切换一致。
- 移动端 bar 从 3 行压到 **1 行**：搜索框 + 「Filters」按钮（带已选条件数徽章，有筛选时反色）。筛选生效后下方出现可横向滑动的条件 chips，点 × 单独取消该条件。
- 弹层内：SCOPE 分段控件（全宽 44px 高）、STATE/CATEGORY 原生 select（≥16px 防 iOS 缩放）+ 说明文案、实时预览计数、**粘底页脚 [Reset] [Show N results]**（主按钮直接告诉你会出来多少条）。带 grabber，支持下拉关闭，Esc/背板关闭，焦点陷阱，`inert` 关掉背景可聚焦性，`prefers-reduced-motion` 降级。
- **语义约定**：分段控件即时生效（它长得像 tab）；两个 select 是草稿，由「Show N results」提交；取消（X/背板/Esc/下拉）会连分段一起回滚到打开前的状态。顺带修掉了旧代码里 `setScope` 只写变量不重跑过滤、导致控件与列表不一致的隐患。
- 行为变化（需用户知悉）：桌面端点 All/National/State 现在会**立即**过滤，不再等 Apply；这是为消除「控件显示 X 但列表是 Y」的不一致。

### 踩坑（重要，两条都是真踩出来的）
- **Astro 的 scoped style 到不了 JS 注入的元素**。JS 用 innerHTML 建的节点没有 `data-astro-cid-*` 属性，`.chip{cid}` 这类规则一律不生效。→ 凡是给注入标记用的样式必须写 `:global(...)`。**顺手发现并修掉一个既有 bug：首页搜索自动补全的下拉项（`.combobox-opt/.co-name/.co-meta`）一直是没样式的裸 `<li>`**。
- **弹层主体是滚动容器时，flex 子项会被压扁**。`.dir-filters` 竖向 flex + `overflow-y:auto` 时，矮视口（横屏 844×390）把 SCOPE 分段控件挤成一条线。解法：`.dir-filters > * { flex-shrink: 0 }`。
- 粘底页脚**别用负 bottom margin** 去对齐（会和 sticky 的约束打架，实测把上方预览行盖掉 2px）。改成表单底部 padding 归零、由页脚自带 padding 收尾。
