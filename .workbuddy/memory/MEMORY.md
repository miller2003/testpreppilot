- **⚠️ OPEN P0 — the Cloudflare edge 403s 8 crawlers that robots.txt explicitly Allows**: GPTBot, ClaudeBot, anthropic-ai, Amazonbot, CCBot, Diffbot, cohere-ai, Bytespider. Honest framing: the *training/knowledge* path is cut, the *retrieval/citation* path is not — but GPTBot/ClaudeBot/Google-Extended bundle training WITH grounding in one token, so unblocking them restores both channels.

## Build / dev environment (non-obvious)
- Astro 5 site. `astro build` / `astro preview` **must run with `dangerouslyDisableSandbox: true`** — the default sandbox's safe-delete shim blocks Vite's `.vite/deps` cleanup and the build silently produces no `dist/`.
- Managed Node only: `export PATH="/c/Users/samja/.workbuddy/binaries/node/versions/22.22.2-3:$PATH"`; call `./node_modules/.bin/astro` (shell wrapper, never prefix with `node`).
- **`rm -rf dist` is not allowed** — safe-delete shim fails closed even with sandbox disabled; `astro build` empties outDir itself.
- **Astro `is:inline` gotcha**: `{expr}` not evaluated in `<script is:inline>`; use `<script is:inline define:vars={{myVar}}>` and `JSON.parse()` it (define:vars injects a JSON string).
- **Scoped-style gotcha**: JS-injected DOM never gets `[data-astro-cid-*]` — styles targeting injected nodes must use `:global(.cls)`; keep injected class names namespaced.
- **Flex-column + `overflow-y:auto` shrinks children** — panel bodies need `.x > * { flex-shrink: 0 }`; sticky footer shouldn't use negative bottom margin.

## Publishing pipeline (verified)
- **The one switch**: `src/data/examCatalog/release-manifest.mjs` `releases = { slug: 'YYYY-MM-DD' }`, consumed only by `isReleased()` at `index.mjs:169`. Hand-editing is safe (manager/server.mjs is a UI, not a daemon).
- Deploy script (current): **`_heat_rank.mjs` → `_batch55_picks.json` → `_deploy_batch_55.mjs`** (wave 3+, demand-ranked). The older `_deploy_batch_30_v2.mjs` (hand-written `BATCH` + `DOUBLE_DAYS`) is superseded but still works. Companions: `_candidates_now.mjs` (pool enumerator), `_cat_balance.mjs`, `_verify55.mjs` (post-build per-page check).
- **Demand ranking ("按热度")**: `_heat_rank.mjs` scores every candidate with `heat = clamp(round(45+12*log10(v/1000)),10,100)`, `v` = estimated annual candidates, from a curated exact-slug `VOL` map (`src:'published'` only where a sponsor states a count, else `estimate` + a reasoning note). It asserts **0 slugs fall to the default floor** — if that assertion ever fires, the new slug needs a `VOL` entry before it can rank honestly. `FAMILY_RULES` caps per batch (AP 5, PRAXIS 4, NCCER 4, MICROSOFT 4, AWS 4, ACCUPLACER 3, NIMS 3 …) — **this cap is what keeps a heat batch from becoming 10 near-identical Praxis/NCCER/ARRT pages**. Global English tests (TOEIC/Duolingo/PTE) are US/English-market-weighted, not raw worldwide counts.
- **Pick only `national`-mode pages** (`e.record` exists); ~123 state rows are `placeholder` → noindex. **Allocate by live coverage, not backlog** — as of 2026-09-16: technology 19%, admissions-academic 12%, trades 9%, insurance/behavioral-health/animal-agriculture 0% are the gaps; legal/healthcare/finance nearly saturated.
- **Always re-run `node _gen_infographics.mjs` after editing the manifest** — `[slug].astro:398` emits the infographic `<img>` unconditionally; missing asset = broken image. Output count = released + 8.
- Manifest date is only a gate; `datePublished` wired via `releaseDateFor(slug)` → schema.org + article:published_time; sitemap lastmod from `releases[slug]` (not build timestamp).
- Waves: wave 1 = 2026-09-02 (30 pages, 2026-08-02→09-02); wave 2 = 2026-09-16 (30 pages, 2026-08-18→09-16); **wave 3 = 2026-10-03 (55 pages, dates 2026-09-04→10-03, max 3/day, 25 of 30 days used)**. Manifest = 175 slugs, **302 indexable candidates left**.
- **Date assignment for a batch**: random draw from the trailing 30-day window ending "today" (UTC), capped at 3/day, then shuffled so heat does not correlate with date. The window deliberately overlaps the previous wave's dates — the manifest is a slug→date map, so several articles legitimately share a day.
- Near-duplicate pairs that must NOT ship in the same batch: `notary-signing-agent` + `nna-certified-notary-signing-agent`; `nccer-electrical` + `nccer-electrician`; `hubspot-inbound-certification` + `hubspot-inbound-marketing-certification`. `_deploy_batch_55.mjs` asserts this and refuses to write.
- Post-release verification: dist page exists, published_time == schema date == manifest date, no noindex, infographic referenced, sitemap loc without trailing slash, lastmod == release date. `_verify55.mjs` automates all of it.
- **⚠️ QA-harness staleness trap**: `_qa/verify-seo-geo.mjs` used to hardcode `2026-09-16` as "newest release" and FAILED on a correct build after wave 3. Fixed to derive `newestRelease = max(Object.values(releases))` from the manifest. **Any QA assertion containing a literal release date will go stale every wave — derive it or don't assert it.**
