# 2026-10-03 — Wave 3: 55 heat-ranked pages released

## What was asked
"按热度再放 55 篇出去，日期往前随机分散 30 天" → release 55 more of the
already-written-but-unreleased pages, ordered by demand, with publication dates
dispersed backwards across the trailing 30 days.

## State on entry
- Working tree clean at `9e4eeac v2`; manifest held **120** slugs (wave 2 ended 2026-09-16).
- `node _candidates_now.mjs` → **357** unreleased, indexable candidates
  (definition: has `record` AND `examDepth[slug]`; all 357 are `scope: national`,
  so the ~123 state rows were never in play).

## What was built
1. **`_heat_rank.mjs`** — demand ranking over the 357-candidate pool.
   - `heat = clamp(round(45 + 12*log10(v/1000)), 10, 100)`, `v` = estimated annual
     candidates. Every one of the 357 slugs is named in the curated `VOL` map
     (**0 floored** to the default — the script asserts this).
   - `src: 'published'` only where a sponsor really states an annual count
     (PSAT/NMSQT 3.5M, AP totals, ServSafe Food Handler, FAA TRUST, LSAT).
     Everything else is `estimate` with a reasoning note.
   - Three global English tests are **US/English-market-weighted** (TOEIC 1M→180k,
     Duolingo 700k→350k, PTE 300k→120k), because their raw worldwide candidate
     counts sit mostly in non-English search markets.
   - `FAMILY_RULES` cap per batch (AP 5, PRAXIS 4, NCCER 4, MICROSOFT 4, AWS 4,
     ACCUPLACER 3, NIMS 3 …) so a batch is never dominated by sibling pages that
     differ only by exam code. **This is the mechanism that makes "按热度" safe** —
     pure volume order would have produced 10+ Praxis/NCCER/ARRT pages at once.
   - Output: `_batch55_picks.json`.
2. **`_deploy_batch_55.mjs`** — validates (unreleased + record + depth), then
   asserts three near-duplicate pairs do NOT ship together
   (`notary-signing-agent`/`nna-…`, `nccer-electrical`/`nccer-electrician`,
   `hubspot-inbound-certification`/`hubspot-inbound-marketing-certification`),
   assigns dates, merges manifest preserving shape + alpha order.
3. **`_verify55.mjs`** — post-build per-page check.

# 2026-10-03 (second pass) — SEO/GEO upgrade: commit 11ce8b8

## Audit findings that drove the work
- **Deployment resolved**: the site is **Cloudflare Pages building from this repo**.
  Proof: `/states` → 301 (a rule that exists ONLY in `public/_redirects`) works,
  and live `/llms.txt` says "120 verified exam guides" = the repo one wave behind.
  **So `public/_headers` takes effect** — the sibling of `_redirects`.
  Caveat: the live site already sends `x-content-type-options`, `referrer-policy`
  and `Cache-Control` that are NOT in the repo, so some edge behaviour is also
  configured in the dashboard. Both can coexist.
- **The 403 P0 re-confirmed, with an exact list**: GPTBot, ClaudeBot, anthropic-ai,
  Amazonbot, CCBot, Diffbot, cohere-ai, Bytespider → 403.
  OAI-SearchBot, ChatGPT-User, Claude-User, PerplexityBot, Google-Extended,
  Googlebot, Bingbot, Applebot, meta-externalagent, and a **fake bot UA** → 200.
  A fake bot passing proves it is a **targeted UA allow/block list**, not generic
  bot protection. Body is `Your request was blocked.` (25 bytes, text/plain).
  **Live robots.txt is byte-identical to the repo — Cloudflare is NOT rewriting it**,
  so the Cloudflare "managed robots.txt" failure mode does not apply here. Only the
  **edge WAF layer** blocks. Nothing in the repo controls it.
- Content layer was already strong (175 exam pages, 94% question H2, 100% tables +
  FAQ, 0 schema/text mismatches) → **no prose was rewritten**.

## What shipped
1. **Agent-readiness surface** — `public/.well-known/{ai-catalog.json, api-catalog,
   openapi.json, agent-skills/index.json, agent-skills/site-content/SKILL.md}`,
   `public/auth.md`, `public/_headers`, robots.txt `Content-Signal` + `Agentmap`.
   `_gen_agent_surface.mjs` is the SSOT and runs from an **`astro:build:start` hook**

2. **Public dataset** — `/data/exam-catalog.json`, `exam-catalog.csv`, `health.json`

5. **WebMCP** — `search_exams` / `get_exam` / `list_exam_categories` from the real

# 2026-10-03 (third pass) — user asked where Cloudflare's AI settings are

## What the user was remembering, confirmed
Cloudflare **replaced the single "Block AI bots" toggle on 2026-09-15** with **three
enforced crawler categories: Search / Agent / Training**. That is the "三个东西".
New-zone default: Training + Agent blocked on pages carrying an ad unit, Search
allowed. The 8 blocked crawlers on this zone are all **Training**-class.

Two dashboard locations that **can disagree, so both must be checked**:
1. `Security → Settings → Configure AI bot policies` — the three category toggles
   (account level). A *saved* preference is what prevents the 9/15 default applying.
2. `Security → Bots → AI Crawl Control → Crawlers` — per-crawler ground truth.
   **Blocking here writes a WAF custom rule**, which is exactly why the block
   survives an allowing robots.txt. Also check `Security → WAF → Custom rules`
   and `Security → Settings → Bot traffic` (Bot Fight Mode must be off).

Safety note worth repeating to the user: Googlebot / Bingbot / Applebot are
**multi-purpose**, evaluated under both Search and Training with the **strictest
rule winning** — so a *category-level* Training block can silently block Googlebot.
Per-crawler blocks are the safe form.

## Deploy verified live
The user pushed. Confirmed from the origin:

  full 5-relation `Link:` header and `x-robots-tag: noindex, follow`.

## New defect found while verifying the live origin
**Every URL 308s to add a trailing slash.** `/best`, `/about`, `/exams/nclex-rn`,
`/categories/technology`, `/guides`, `/privacy` → all `308 → /x/`, while canonical,
internal links and the sitemap all use the no-slash form. So every internal
navigation takes an extra hop and each canonical URL redirects instead of serving
200. This is **pre-existing and site-wide**, not introduced by this pass (the same
`trailingSlash: 'never'` + `build.format: 'directory'` interaction already
documented in user-level memory).

Two possible fixes — **deliberately not applied yet, needs the user's choice**:
- **(a) Prescribed**: set `html_handling: 'drop-trailing-slash'` on the Cloudflare
  assets/Worker config. Keeps the designed no-slash URLs. Outside the repo (no
  wrangler config exists in it).
- **(b) Repo-side**: flip Astro to `trailingSlash: 'always'` so canonical, links and
  sitemap carry the slash and match what the edge serves. Much bigger diff, and
  `_verify55.mjs` asserts a no-slash sitemap `loc`, so the harness needs updating.
