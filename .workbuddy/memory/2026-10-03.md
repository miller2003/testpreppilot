# 2026-10-03 — Wave 3: 55 heat-ranked pages released

## What was asked
"按热度再放 55 篇出去，日期往前随机分散 30 天" → release 55 more of the
already-written-but-unreleased pages, ordered by demand, with publication dates
dispersed backwards across the trailing 30 days.

## State on entry
- Working tree clean at `9e4eeac v2`; manifest held **120** slugs (wave 2 ended 2026-09-16).
- `node _candidates_now.mjs` → **357** unreleased, indexable candidates
  (definition: has `record` AND `examDepth[slug]`; all 357 are `scope: national`,
  so the ~123 state rows were never in play).

## What was built
1. **`_heat_rank.mjs`** — demand ranking over the 357-candidate pool.
   - `heat = clamp(round(45 + 12*log10(v/1000)), 10, 100)`, `v` = estimated annual
     candidates. Every one of the 357 slugs is named in the curated `VOL` map
     (**0 floored** to the default — the script asserts this).
   - `src: 'published'` only where a sponsor really states an annual count
     (PSAT/NMSQT 3.5M, AP totals, ServSafe Food Handler, FAA TRUST, LSAT).
     Everything else is `estimate` with a reasoning note.
   - Three global English tests are **US/English-market-weighted** (TOEIC 1M→180k,
     Duolingo 700k→350k, PTE 300k→120k), because their raw worldwide candidate
     counts sit mostly in non-English search markets.
   - `FAMILY_RULES` cap per batch (AP 5, PRAXIS 4, NCCER 4, MICROSOFT 4, AWS 4,
     ACCUPLACER 3, NIMS 3 …) so a batch is never dominated by sibling pages that
     differ only by exam code. **This is the mechanism that makes "按热度" safe** —
     pure volume order would have produced 10+ Praxis/NCCER/ARRT pages at once.
   - Output: `_batch55_picks.json`.
2. **`_deploy_batch_55.mjs`** — validates (unreleased + record + depth), then
   asserts three near-duplicate pairs do NOT ship together
   (`notary-signing-agent`/`nna-…`, `nccer-electrical`/`nccer-electrician`,
   `hubspot-inbound-certification`/`hubspot-inbound-marketing-certification`),
   assigns dates, merges manifest preserving shape + alpha order.
3. **`_verify55.mjs`** — post-build per-page check.

## Harness bug found and fixed
`_qa/verify-seo-geo.mjs` **hardcoded `2026-09-16`** as "newest release" (lines 96
and 105), so it FAILED on a correct build after this wave. Rewrote both to derive
`newestRelease = max(Object.values(releases))` from the manifest, and derive the
probe exam's date from `releases['sat-exam']`. **Pattern to remember: any QA
assertion containing a literal release date will go stale every wave.**
