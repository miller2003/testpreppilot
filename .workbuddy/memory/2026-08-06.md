## 【补丁】考试页手机端"右边一半显示不出来"真机复现修复（用户真机反馈）
复检结论"零问题"被用户真机打脸：具体考试页在手机上右侧一半被裁切。

### 根因（关键认知修正）
- 复检只看"栅格 collapse 规则存在 + min(100%) 包裹"是**不够的**——真机溢出来自 flex/grid item 的 `min-width:auto` 默认行为，而不是栅格定义。
- 考试页 `.two-column-content` 在 ≤900px 塌成单列 `grid-template-columns:1fr`，但它的网格子项 `<main class="main-article">` 仍默认 `min-width:auto`；其内部 `.eg-sources a`（官方注册长 URL）等长不可断字符串作为 flex item 也保持 `min-width:auto`。
- 长 token 使该单列轨道被迫超出视口宽度 → `body{overflow-x:clip}`（裁切而非滚动）把超出部分直接裁掉 → 用户看到"右边一半显示不出来"。
- 旧 `responsive.css` 的 `min-width:0` 重置只作用于 `main :where(section,article,div,li,ul,ol)`（即 main 的**后代**），**从不作用于 `main` 本身 / 网格子项**，且 `word-break:break-word` 不减小 min-content，所以 flex item 仍无法收缩。

### 修复（responsive.css 修正层 + [slug].astro）
- `min-width:0` 选择器扩展到内联元素 `a/span/code/pre/dl/dt/dd/blockquote/figure/table/td/th`，并显式对 `.two-column-content`、`.two-column-content > *`、`main.main-article` 置 0（覆盖考试页网格子项）。
- 新增 `main a, main span, main code, main pre { overflow-wrap: anywhere; word-break: break-word }` —— `overflow-wrap:anywhere` 能减小 min-content，使轨道在 360px 收缩而非溢出（break-word 仅视觉断行、不减 min-content）。
- `main pre { max-width:100%; overflow-x:auto; white-space:pre-wrap }`。
- `[slug].astro` ≤640px：`.eg-step-dur { white-space: normal }`（原 nowrap 在窄屏可推宽行）。
- 验证：构建成功；已编译产物确认 `.two-column-content,.two-column-content>*,main.main-article{min-width:0}` 与 `main a,main span,main code,main pre{overflow-wrap:anywhere;...}` 存在；考试页链接的 `_credential_.Cmn8rwTe.css` 含本修复；exam CSS 无 >viewport 的固定宽、min-width 仅 0 与表格内 150px(在 overflow-x:auto 滚动容器内，安全)。
- 提交 d99d2c4 → push origin/main（c2982cb..d99d2c4）。仅 git add 2 个前端文件，数据/scratch 仍按规范未提交。

### 可复用经验（响应式溢出排查 checklist）
1. 真机/无头浏览器测宽优先；静态审计"collapse 规则"会漏掉 min-width:auto 类溢出。
2. 横向溢出三件套必须同时：html overflow-x:hidden + body overflow-x:clip + main 子项 min-width:0；且 `:where()` 重置要覆盖到 **元素自身及网格/flex 直接子项**，而不仅是后代。
3. 长不可断字符串（URL/code）的 flex/grid item：光 `word-break:break-word` 不够，需 `overflow-wrap:anywhere` 才能真正让 item 收缩。
4. 表格用 `overflow-x:auto` 包裹（滚动容器），其 min-width 不向外传导。
