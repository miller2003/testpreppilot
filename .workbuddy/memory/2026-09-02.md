### 日期机制的坑（重要）
exam 页原先**只传 `dateModified`**，`datePublished` 全站回退到 `BaseLayout` 的
`SITE_UPDATED = '2026-08-06'` 常量 —— 也就是说 manifest 里的日期此前**只是构建开关，
页面上任何地方都不显示**。本次：
- `release-manifest.mjs` 新增 `releaseDateFor(slug)`
- `[slug].astro` 传 `datePublished={releaseDateFor(exam.slug)}`（`article:published_time` 同步生效）
- `astro.config.mjs` 的 sitemap `serialize()`：`/exams/<slug>` 的 lastmod 改用该页真实发布日期。
  原先是 `lastmod: new Date()`（全站统一构建时间），Google 会把这种信号当噪音丢弃。

### 51 个州页 = 教科书级 doorway pages（实测）
- 1,275 个页面对，**100% 相似度 ≥90%**，平均 98.3%，最高 99.7%（NC vs SC / ND vs SD）
- 根因：48/51 州 `getExamsByState()` 返回 0 —— 全站只有 3 个 state-scope 考试已发布（TX/CA/FL 房产执照）
- 这 48 页渲染的是同一组 5 张全国证书卡（enrolled-agent / osha-10 / osha-30 / epa-608 / cpa-exam），
  唯一变量是州名、首府、区域、邻近州列表
- 额外伤害：`StateDirectory` 在每个州页底部输出 51 条链接 → 51×51 = 2,601 条内部链接形成闭环，
  权重锁死在 51 个低质页之间，无法流向 90 个考试页

### 顺序颠倒（用户直觉正确的地方）
- `allExamsFull` = 5,785 条，只发布 98 条；未发布的 5,687 条几乎全是
  `buildStateExams()` 的 51 模板 × 51 辖区 组合

  但 URL 层先上线了 51 个空壳 → 应向 Google 提交的样本全是不及格的

`getStaticPaths` 用 `buildDirectory()`，自动 `.filter(cat => cat.total > 0)`：
26 个分类定义只生成 21 个页面，随考试发布自动增减。**考试驱动，而非数据全量驱动。**
