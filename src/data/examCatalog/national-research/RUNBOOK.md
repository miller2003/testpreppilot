# National research — runbook

3,186 national exams, researched in small chunks so the work survives interruptions.
Everything here is resumable: re-running any step is safe and idempotent.

## Where things live

```
_input/batchNN.json          the original 42 batches (source of truth for slugs)
_input/chunks/bNN-pM.json    110 subagent-sized chunks (~29 exams each)
_input/chunks/manifest.json  chunk index
_chunks/bNN-pM.mjs           ← research output, one file per chunk (what subagents write)
batchNN.mjs                  ← AUTO-GENERATED by mergeChunks.mjs. Do not hand-edit.
index.mjs                    merge/normalise layer consumed by the site
_BRIEF.md                    the brief handed to every research subagent
NATIONAL_SCHEMA.md           (in ../) the field-by-field schema
```

## The loop

```bash
cd src/data/examCatalog/national-research

node status.mjs              # how far along, and which chunks are still owed
node status.mjs --next 6     # the next 6 chunk ids to hand out

#   ... dispatch one subagent per chunk id, each told to read _BRIEF.md
#   ... and write _chunks/<chunkId>.mjs

node mergeChunks.mjs         # fold delivered chunks into the 42 batch modules
node validateNational.mjs    # must end in "PASS — 0 errors"
```

Then, occasionally:

```bash
cd ../../../..                       # repo root
node node_modules/astro/astro.js build
```

## Dispatching a research subagent

One chunk per subagent. The prompt only needs to say:

> Repo root: `<abs path>`. Your assignment is chunk **bNN-pM**.
> Read `src/data/examCatalog/national-research/_BRIEF.md` first and follow it exactly,
> then `NATIONAL_SCHEMA.md`, then your input
> `src/data/examCatalog/national-research/_input/chunks/bNN-pM.json`, then
> `_chunks/b03-p01.mjs` as a correctly-formatted model.
> Write `_chunks/bNN-pM.mjs`. Do not write all records in one call — it truncates;
> write 6-8 at a time and re-verify after every pass.

Repeat the structural rules in the prompt — subagents get these wrong otherwise:

- exam → program link is the **`body`** string, never `programId`
- `examMeta` keys: questions, time, pass, fee, format, admin
- `examEssentials` is an array of `[label, value]` pairs
- `roadmap` is an array of strings
- every exam needs `tagline`, `timeline`, `costBreakdown`
- exactly one `export default { programs, exams };`

## Failure modes and their fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `batchNN.mjs` won't parse | a pre-chunking subagent truncated it mid-object, or emitted `key: ' \'value'` | `node repairBatch.mjs NN` — salvages every complete record and backs the original up to `.orig` |
| `duplicate program dossier` error | two chunks minted a dossier for the same body under different ids | `mergeChunks.mjs` collapses them automatically, keeping the richer one — just re-run it |
| chunk file has a stray `];` mid-array | Edit-append landed after the array closed | fix by hand; `node --check` locates it |
| Astro build hangs at the very end | the sandbox bulk-delete guard blocks Astro's `cleanServerOutput` of `dist/pages` | the HTML is already written by then; kill the build and delete `dist/pages` from Node |
| `N record(s) had a slug not present in any _input batch` | a subagent invented or misspelled a slug | grep the chunk file for the bad slug and correct it against the input JSON |

## Invariants

- A slug appears in exactly one `_input/batchNN.json`, so `mergeChunks.mjs` always
  re-files a record into the right batch no matter which chunk produced it.
- A program dossier is written into exactly **one** batch file; `index.mjs` pools all
  42 into a single registry keyed by body.
- Re-running a chunk overwrites that chunk's records only — other work is untouched.
