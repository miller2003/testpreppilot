01做得好的部分

内容深度是这个站真正的护城河

pSEO 站最常见的死法是「1 万个页面共用 300 词模板」。这个站正好相反。我剥离了 header/footer/nav，只统计 <main> 内的正文： 中位数 3,933 词，P90 达 6,484 词，最长 10,990 词。全站平均样板文字只有 89 词、占页面 2.7%—— 意味着几乎每一个字都是这个页面独有的。这个数字我很少在程序化站上见到。

反编造纪律是真的在执行，不是写在文档里好看

抽查 nclex-rn：薪资段落 296 词，直接引 BLS SOC 29-1141 与 2024 年 5 月中位数 $93,600，并链到 bls.gov 原页； 通过率段落 337 词，明确写出 NCSBN 不公布队列通过率，而不是编一个百分比。 全站 413 个页面引用 bls.gov，0 个考试页缺少外部权威来源，平均每页引 2.12 个外部域。 这在 Google 的 helpful-content 与 E-E-A-T 判定下是实打实的加分项。

站点架构近乎教科书

从首页 BFS 遍历，最大点击深度只有 2（1 层 76 页，2 层 572 页），全站唯一「孤儿页」是 /404——这本来就不该被链接。 考试页入链中位数 17、P10 为 9、平均出链 36.3 条，权重分布均匀，没有出现「头部页吃掉全部内链」的典型病灶。

顺带修正一个误判 此前报告有误

项目里 _audit_now.py 报告「649 个孤儿页」，这是脚本 bug 不是站点问题：url_to_file 字典在同一个循环里边遍历边填充， 处理到首页时字典几乎是空的，导致首页 94 条内链全被判为「指向不存在的页面」而丢弃，BFS 自然只走得到根节点。 我在 _deep_audit.py 里改为两遍扫描（先建全量 URL 集合，再解析链接），真实孤儿页 = 1。

02致命短板：两个业务层面的洞

P0-1　全站没有任何数据埋点 最高优先级

构建产物里只有 Astro 自己的 ClientRouter.js 和 page.js，没有 GA4、没有 Plausible、没有任何统计脚本， 首页也没有 Search Console 验证 meta。

这意味着：你有 650 个页面在跑，但不知道哪 20 个带来了 80% 的流量、哪些页面有曝光却零点击（标题该改）、 哪些页面进了索引哪些没进。pSEO 的核心打法是「大量铺 → 看数据 → 砍掉无效页 + 加码有效页」， 没有数据，这个循环根本转不起来，后续所有优化都只能靠猜。

修复成本：约 30 分钟。在 BaseLayout.astro 的 <head> 加 GA4 或 Plausible 片段， GSC / Bing 站长平台各验证一次并提交 sitemap。这是投入产出比最高的一件事，没有之一。

P0-2　550 个主力页面上没有任何变现位 收入=0

AffiliateBox.astro 和 ProviderTable.astro 写得很完整，但它们只被 ExamGuide.astro 引用， 而 ExamGuide 只服务于 /paths/*（8 页）和 /[state]/[credential]（3 页）——合计 11 个页面。

承担绝大部分搜索意图的 /exams/[slug] 那 550 个页面，模板里完全没有引入这两个组件， 从头到尾没有一个联盟链接、没有一个转化 CTA。用户读完 4,000 词的高质量攻略，然后……就走了。 换句话说，98% 的内容资产目前没有接上任何收入管道。

建议：在 [slug].astro 的 resourceComparison 区块后、以及 examDay 区块后各插入一个 provider 模块，复用现成组件与 InlineDisclosure。注意保持披露合规（站点已有 /disclosure，别丢）。

P1-2　sitemap 需要在真实部署环境复核 待验证

robots.txt 对外声明 Sitemap: https://testpreppilot.com/sitemap-index.xml，但本次构建的 dist/ 里没有生成任何 sitemap。

根因已定位：astro build 在收尾清理临时目录时被本地沙箱的安全删除机制拦截并抛错， 而 @astrojs/sitemap 是挂在 astro:build:done 钩子上的——构建中途抛错，钩子就不会执行。 旧备份 dist_bak_1785430319/ 里 sitemap-index.xml 与 sitemap-0.xml 都在， 说明正常环境下功能是好的，这是本地环境问题而非代码缺陷。

但仍需确认两件事：① 线上 CI/部署平台的构建日志里 sitemap 确实生成了； ② 同一个报错还会让 dist/pages/ 与 dist/chunks/ 两个构建临时目录残留（本次就残留了）， 如果直接把这样的 dist 传上线，等于把编译中间产物暴露在公网。部署前建议加一步校验。

P1-3　487 条 meta description 被截断成「…」结尾 占全站 75%

clampMeta() 把长文本硬切到 155 字符再补省略号。虽然长度合规（超 160 的为 0）， 但 649 个可索引页里有 487 条描述是半句话戛然而止的。这类描述在 SERP 里说服力弱， Google 也更倾向于直接弃用、自行改写摘要——你精心设计的关键词尾巴就白费了。

建议：对流量最高的那批页面，改为「专门写一句 150 字符以内的完整描述」而不是截断长文本。 数据层可加一个可选的 metaDescription 字段，有则用、无则回退到现在的截断逻辑，改动面很小。

04内容层面：机会与风险

全站 650 个页面，img 标签数为 0

一张图都没有。OG 图（og-image.png / og-exam.png / og-state.png）是有的，但那只在社交分享时露面， 正文里没有任何图片、图表或示意图。对一个考试攻略站来说这是明显的机会成本： 放弃了 Google 图片搜索入口，也失去了「考试内容占比饼图」「备考时间线」这类天然适合可视化、且能显著拉长停留时间的内容形态。 好消息是数据层已经有 topics[].weight、studyPlan.weeks 这些结构化字段， 用构建期 SVG 渲染即可批量生成，不增加运行时负担。

48 个页面偏薄，集中在州级技工执照

正文最短的 11 个页面不足 800 词，48 个不足 1,500 词——相对全站 3,933 的中位数落差明显。 最薄的一批高度集中：florida/california/new-york-journeyman-plumber-license（639 / 646 / 655 词）、 pennsylvania-journeyman-electrician-license、new-york-hvac-contractor-license、texas-general-contractor-license。 这些恰恰是商业价值不低的词，建议优先补足到 2,000 词以上，重点补本州考试细则、报名流程与费用明细。

06综合评分

坦率地说：这个站的内容和工程完成度，已经超过我见过的绝大多数程序化 SEO 项目—— 反编造纪律、BLS 溯源、2.7% 的样板占比、深度 2 的扁平架构，这些都是需要真功夫才能做到的。 问题恰恰不在 SEO 本身，而在于它现在是一件没有装仪表、也没有接变速箱的精密机器。 先花一小时补上埋点和变现位，再谈内容扩量——否则铺得越多，浪费得越多。

审计方法：对 dist/ 全部 650 个 HTML 构建产物做全量解析（非抽样）。正文词数剥离 header/footer/nav 后仅统计 <main>； 重复度采用 8-gram shingle + Jaccard 相似度，经倒排索引候选剪枝；可达性与点击深度以首页为根做 BFS。 审计脚本：_deep_audit.py，明细数据：_deep_audit.json。
